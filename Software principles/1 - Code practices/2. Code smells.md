# Code Smells

Code smells are symptoms in the source code that indicate a deeper problem. They are not bugs — the code may still work — but they signal poor design that will make the codebase harder to maintain and evolve over time.

The term was introduced by Kent Beck and popularized by Martin Fowler in *Refactoring: Improving the Design of Existing Code*.

<a href="https://refactoring.guru/refactoring/smells" target="_blank">Code Smells – Refactoring Guru</a>

## Long Function

A function that tries to do too much. Hard to read, test, and reuse.

*Example:*

```typescript
// bad — one function doing validation, business logic, formatting and saving
function submitOrder(order: Order): string {
  if (!order.items.length) throw new Error("Empty order");
  if (!order.userId) throw new Error("Missing user");
  const total = order.items.reduce((sum, i) => sum + i.price * i.quantity, 0);
  const discounted = total > 100 ? total * 0.9 : total;
  const formatted = `Order total: $${discounted.toFixed(2)}`;
  db.save({ ...order, total: discounted });
  return formatted;
}

// good — responsibilities split into small focused functions
function validateOrder(order: Order): void {
  if (!order.items.length) throw new Error("Empty order");
  if (!order.userId) throw new Error("Missing user");
}

function calculateTotal(order: Order): number {
  const total = order.items.reduce((sum, i) => sum + i.price * i.quantity, 0);
  return total > 100 ? total * 0.9 : total;
}

function submitOrder(order: Order): string {
  validateOrder(order);
  const total = calculateTotal(order);
  db.save({ ...order, total });
  return `Order total: $${total.toFixed(2)}`;
}
```

## Long Parameter List

Functions with too many parameters are hard to call and easy to misuse.

*Example:*

```typescript
// bad
function createUser(name: string, email: string, age: number, role: string, city: string) {}

// good — group related data into an object
interface CreateUserParams {
  name: string;
  email: string;
  age: number;
  role: string;
  city: string;
}
function createUser(params: CreateUserParams) {}
```

## Duplicate Code

The same logic repeated in multiple places. When requirements change, every copy must be updated — and one is always forgotten.

*Solution:* Extract the repeated logic into a shared function or class.

## Dead Code

Code that is never executed: unreachable branches, unused variables, commented-out blocks, functions that are never called.

*Example:*

```typescript
// bad
function getDiscount(type: string): number {
  if (type === "vip") return 0.2;
  if (type === "member") return 0.1;
  if (type === "superuser") return 0.5; // this type no longer exists in the system
  return 0;
}
```

*Solution:* Delete it. Git keeps the history — you can always recover it.

## Large Class (God Object)

A class that knows too much or does too much. It accumulates responsibilities over time until it becomes the center of the entire system.

*Solution:* Apply the Single Responsibility Principle (SRP) — split it into smaller, focused classes.

## Magic Numbers / Magic Strings

Raw values with no explanation scattered throughout the code.

*Solution:* Replace with named constants. See Clean Code → No Magic Numbers.

## Deeply Nested Code (Arrow Anti-Pattern)

Excessive nesting makes code hard to follow. Each level of indentation adds cognitive load.

*Example:*

```typescript
// bad
function processOrder(order: Order | null) {
  if (order) {
    if (order.items.length > 0) {
      if (order.isPaid) {
        ship(order);
      }
    }
  }
}

// good — use early returns (guard clauses)
function processOrder(order: Order | null) {
  if (!order) return;
  if (!order.items.length) return;
  if (!order.isPaid) return;
  ship(order);
}
```

## Feature Envy

A method that seems more interested in the data of another class than its own. A sign that the method is in the wrong place.

*Example:*

```typescript
// bad — Order is doing Discount's job
class Order {
  getDiscountedTotal(discount: Discount): number {
    return this.total - (this.total * discount.rate) - discount.fixedAmount;
  }
}

// good — move the logic to where the data lives
class Discount {
  apply(total: number): number {
    return total - (total * this.rate) - this.fixedAmount;
  }
}
```
