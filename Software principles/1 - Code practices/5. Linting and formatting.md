# Linting and Formatting

Linting and formatting are automated tools that enforce code quality and style consistency without manual effort. They eliminate entire categories of review comments ("missing semicolon", "wrong indentation") so code reviews can focus on logic and design.

## Linting vs Formatting
 
| | Linting | Formatting |
|---|---|---|
| **Purpose** | Finds bugs and bad practices | Enforces visual style |
| **Examples** | Unused variables, missing `await` | Indentation, quotes, line length |
| **Fix** | Some auto-fixable, some require manual changes | Fully automatic |

## Some tools by Stack
 
| Stack | Linter | Formatter | Notes |
|---|---|---|---|
| **JS/TS** | ESLint | Prettier | Industry standard. Used together. |
| **Java** | Checkstyle, PMD, SpotBugs | Google Java Format, Eclipse Formatter | Checkstyle = style rules. PMD = bad practices. SpotBugs = potential bugs. |
| **Spring Boot** | Checkstyle, PMD | Spring Java Format | Spring projects use their own formatter config. |
| **Python** | Flake8, Pylint, Ruff | Black, autopep8 | Ruff is a modern fast alternative that does both lint and format. |
