# Testing

Software testing is the practice of verifying that code behaves as expected. Tests catch bugs before they reach production, document intended behavior, and give confidence when refactoring or adding features.

<a href="https://jestjs.io/docs/getting-started" target="_blank">Jest Documentation</a>
<a href="https://vitest.dev/guide/" target="_blank">Vitest Documentation</a>

## The Testing Pyramid

The testing pyramid describes three levels of tests, each with a different scope and cost:

```
        /\
       /E2E\        ← few, slow, expensive
      /------\
     /Integr. \     ← some, medium speed
    /----------\
   /    Unit    \   ← many, fast, cheap
  /______________\
```

- **Unit tests** — test a single function or class in isolation.
- **Integration tests** — test how multiple components work together.
- **End-to-End (E2E) tests** — test the entire application from the user's perspective.

## Unit Tests

Test the smallest unit of code (a function or method) in complete isolation. Dependencies are replaced with mocks or stubs.

**Install (Jest + TypeScript):**

```console
npm install --save-dev jest ts-jest @types/jest
```

*Example:*

```typescript
// calculateDiscount.ts
export function calculateDiscount(price: number, rate: number): number {
  if (rate < 0 || rate > 1) throw new Error("Rate must be between 0 and 1");
  return price * (1 - rate);
}
```

```typescript
// calculateDiscount.test.ts
import { calculateDiscount } from "./calculateDiscount";

describe("calculateDiscount", () => {
  it("applies the discount correctly", () => {
    expect(calculateDiscount(100, 0.1)).toBe(90);
  });

  it("returns full price when rate is 0", () => {
    expect(calculateDiscount(100, 0)).toBe(100);
  });

  it("throws when rate is out of range", () => {
    expect(() => calculateDiscount(100, 1.5)).toThrow("Rate must be between 0 and 1");
  });
});
```

## Integration Tests

Test how multiple parts of the system work together. Common for testing service + database, controller + service, etc.

*Example (testing an Express route with a real database):*

```typescript
import request from "supertest";
import app from "../app";
import { db } from "../database";

describe("POST /users", () => {
  afterEach(async () => {
    await db.collection("users").deleteMany({});
  });

  it("creates a user and returns 201", async () => {
    const res = await request(app)
      .post("/users")
      .send({ name: "Ana", email: "ana@example.com" });

    expect(res.status).toBe(201);
    expect(res.body).toMatchObject({ name: "Ana", email: "ana@example.com" });
  });
});
```

## End-to-End (E2E) Tests

Simulate real user actions in a browser. Test the full stack — frontend, backend, and database.

**Common tool:** Playwright or Cypress.

*Example (Playwright):*

```typescript
import { test, expect } from "@playwright/test";

test("user can log in", async ({ page }) => {
  await page.goto("http://localhost:3000/login");
  await page.fill('[name="email"]', "user@example.com");
  await page.fill('[name="password"]', "secret123");
  await page.click('button[type="submit"]');
  await expect(page).toHaveURL("/dashboard");
});
```

## TDD – Test-Driven Development

Write the test before the implementation. The cycle is: **Red → Green → Refactor**.

1. **Red** — write a test that fails (the feature doesn't exist yet).
2. **Green** — write the minimal code to make the test pass.
3. **Refactor** — clean up the code without breaking the test.

*Example:*

```typescript
// 1. Red — test written, function doesn't exist yet
it("should return the sum of two numbers", () => {
  expect(add(2, 3)).toBe(5); // fails
});

// 2. Green — minimal implementation
function add(a: number, b: number): number {
  return a + b;
}

// 3. Refactor — code is already clean here, nothing to change
```

## Mocks and Stubs

Replace real dependencies (databases, APIs, services) with controlled fakes in unit tests.

```typescript
// mocking a dependency with Jest
import { sendEmail } from "./emailService";

jest.mock("./emailService");
const mockSendEmail = sendEmail as jest.MockedFunction<typeof sendEmail>;

it("calls sendEmail after registration", async () => {
  mockSendEmail.mockResolvedValue(undefined);

  await registerUser({ name: "Ana", email: "ana@example.com" });

  expect(mockSendEmail).toHaveBeenCalledWith("ana@example.com", "Welcome!");
});
```

## Common Jest Matchers

```typescript
expect(value).toBe(42);                    // strict equality (===)
expect(value).toEqual({ id: 1 });          // deep equality
expect(value).toBeTruthy();
expect(value).toBeNull();
expect(value).toBeUndefined();
expect(arr).toContain("item");
expect(str).toMatch(/pattern/);
expect(fn).toThrow("error message");
expect(mock).toHaveBeenCalled();
expect(mock).toHaveBeenCalledWith("arg");
expect(mock).toHaveBeenCalledTimes(2);
```
