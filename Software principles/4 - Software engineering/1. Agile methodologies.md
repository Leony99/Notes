# Agile Methodologies

Agile is a set of values and principles for software development that prioritizes delivering working software in short cycles, embracing change, and fostering collaboration between teams and stakeholders.

Agile is not a specific process — it is a philosophy. **Scrum**, **Kanban**, and **XP** are concrete frameworks that implement agile values.

<a href="https://agilemanifesto.org/" target="_blank">Agile Manifesto</a>

## The Agile Manifesto (2001)

Four core values:

1. **Individuals and interactions** over processes and tools.
2. **Working software** over comprehensive documentation.
3. **Customer collaboration** over contract negotiation.
4. **Responding to change** over following a plan.

## Scrum

Scrum is an iterative framework organized around fixed-length cycles called **Sprints** (usually 1–2 weeks). At the end of each sprint, a potentially shippable product increment is delivered.

**Key roles:**
- **Product Owner** — prioritizes the backlog, represents business needs.
- **Scrum Master** — facilitates the process and removes blockers.
- **Development Team** — self-organizing team that delivers the work.

**Key artifacts:**
- **Product Backlog** — ordered list of all features, bugs, and improvements.
- **Sprint Backlog** — subset of items committed to for the current sprint.
- **Increment** — the working product at the end of each sprint.

**Key ceremonies:**
- **Sprint Planning** — team selects and plans work for the sprint.
- **Daily Standup** — 15-minute sync: what did I do, what will I do, any blockers?
- **Sprint Review** — demonstrate the increment to stakeholders.
- **Sprint Retrospective** — reflect on what went well and what to improve.

## Kanban

Kanban is a flow-based approach that visualizes work in progress and limits how much work can be in each stage simultaneously. Unlike Scrum, there are no fixed sprints or roles — work flows continuously.

**Core practices:**
- **Visualize workflow** — use a board with columns (To Do, In Progress, Done, etc.).
- **Limit WIP (Work in Progress)** — each column has a max number of items allowed. Forces the team to finish before starting more.
- **Manage flow** — track cycle time (how long an item takes from start to done).

**When to use:**
- Teams doing support, bug fixes, or maintenance where work arrives continuously.
- When you want to improve flow without changing team structure.

## XP – Extreme Programming

XP is an agile framework focused on technical excellence and engineering practices. It pushes good practices to the extreme.

**Key practices:**
- **Test-Driven Development (TDD)** — write tests before writing code.
- **Pair Programming** — two developers work together on the same machine.
- **Continuous Integration** — integrate and test code multiple times per day.
- **Refactoring** — continuously improve code structure without changing behavior.
- **Small Releases** — release frequently in small increments.
- **Simple Design** — build the simplest thing that works. See YAGNI.

## Scrum vs Kanban

| | Scrum | Kanban |
|---|---|---|
| **Cadence** | Fixed sprints | Continuous flow |
| **Roles** | PO, SM, Dev Team | No required roles |
| **Planning** | Per sprint | On demand |
| **Best for** | Feature development | Maintenance, support |
| **Change mid-cycle** | Not recommended | Allowed anytime |
