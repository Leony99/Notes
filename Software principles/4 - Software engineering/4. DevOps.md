# DevOps

DevOps is a culture and set of practices that unify software development (Dev) and IT operations (Ops). The goal is to shorten the development lifecycle and deliver high-quality software continuously.

DevOps is not a tool or a role — it is a mindset that breaks down the wall between teams that write code and teams that deploy and maintain it.

## Core Principles

- **Collaboration** — Dev and Ops work together, not in silos.
- **Automation** — automate everything: builds, tests, deployments, infrastructure.
- **Continuous Delivery** — code should always be in a deployable state.
- **Monitoring and Feedback** — observe production, feed insights back into development.
- **Infrastructure as Code** — manage infrastructure using code and version control.

## Infrastructure as Code (IaC)

Define and provision infrastructure (servers, databases, networks) using configuration files instead of manual setup. Infrastructure becomes reproducible, versioned, and auditable.

**Common tools:**
- **Terraform** — provisions cloud resources (AWS, GCP, Azure) from HCL config files.
- **Ansible** — automates server configuration and application deployment.
- **AWS CloudFormation** — IaC specific to AWS, using YAML/JSON templates.

*Example (Terraform — creating an AWS S3 bucket):*

```hcl
resource "aws_s3_bucket" "my_bucket" {
  bucket = "my-app-assets"

  tags = {
    Environment = "production"
    Project     = "my-app"
  }
}
```

## Containerization – Docker

Docker packages an application and all its dependencies into a portable container that runs consistently across any environment. See Techs → (General)Tools - Docker.

<a href="https://docs.docker.com/" target="_blank">Docker Documentation</a>

**Key concepts:**
- **Image** — a read-only template with instructions for creating a container.
- **Container** — a running instance of an image.
- **Dockerfile** — the recipe for building an image.
- **Docker Compose** — tool for defining and running multi-container applications.

*Example (Dockerfile for a Node.js app):*

```dockerfile
FROM node:20-alpine

WORKDIR /app

COPY package*.json ./
RUN npm ci --omit=dev

COPY . .

EXPOSE 3000
CMD ["node", "dist/server.js"]
```

*Example (docker-compose.yml — app + database):*

```yaml
services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: mongodb://db:27017/myapp
    depends_on:
      - db

  db:
    image: mongo:7
    volumes:
      - mongo_data:/data/db

volumes:
  mongo_data:
```

## Container Orchestration – Kubernetes

Kubernetes (K8s) automates deployment, scaling, and management of containerized applications across a cluster of machines.

<a href="https://kubernetes.io/docs/home/" target="_blank">Kubernetes Documentation</a>

**Key concepts:**
- **Pod** — the smallest deployable unit; one or more containers running together.
- **Deployment** — defines the desired state (how many replicas, which image).
- **Service** — exposes a set of pods as a network endpoint.
- **Ingress** — manages external HTTP access to services.

## Monitoring and Observability

Running code in production requires visibility into its behavior.

**Three pillars of observability:**

- **Logs** — records of events. Tools: Winston, Pino (Node.js), ELK Stack.
- **Metrics** — numerical measurements over time (CPU, memory, request rate). Tools: Prometheus, Grafana.
- **Traces** — track a request as it flows through multiple services. Tools: Jaeger, OpenTelemetry.

*Example (basic logging with Winston in Node.js):*

```typescript
import winston from "winston";

const logger = winston.createLogger({
  level: "info",
  format: winston.format.json(),
  transports: [
    new winston.transports.Console(),
    new winston.transports.File({ filename: "logs/error.log", level: "error" }),
  ],
});

logger.info("Server started on port 3000");
logger.error("Database connection failed", { error: err.message });
```

## DevOps Toolchain Overview

|---|---|

| **Test** | Jest, Vitest, Playwright |
