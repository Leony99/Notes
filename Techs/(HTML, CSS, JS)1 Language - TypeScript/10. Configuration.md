# Configuration

The `tsconfig.json` file configures the compiler.

<a href="https://www.typescriptlang.org/tsconfig/" target="_blank">TSConfig Reference</a>

*Example:*

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "rootDir": "src",
    "outDir": "dist",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "sourceMap": true
  },
  "include": ["src"],
  "exclude": ["node_modules", "dist"]
}
```

## Main options

- **target**: ECMAScript version to compile to.
- **module**: Import module format.
- **moduleResolution**: How imports are found. Use `Bundler` with Vite and Webpack.
- **rootDir**, **outDir**: Source and output directories.
- **strict**: Enables all strict checks. Always use it.
- **noUncheckedIndexedAccess**: `array[0]` also includes `undefined`.
- **esModuleInterop**: Allows `import x from` with CommonJS modules.
- **skipLibCheck**: Skips the checking of `.d.ts` files, making it faster.
- **sourceMap**: Generates maps to debug the original code.
- **noEmit**: Only checks the types. Used when another tool generates the JavaScript.
- **jsx**: How JSX is compiled (`react-jsx` for React).
- **paths**: Import aliases.

## Strict checks

- **strictNullChecks**: `null` and `undefined` must be handled.
- **noImplicitAny**: Parameters without a type are an error.
- **strictFunctionTypes**: Stricter checks of function parameters.

## Path aliases

*Example:*

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

```typescript
import { Button } from "@/components/Button";
```

OBS: `paths` only changes how TypeScript finds the files. The bundler or runtime needs the same alias.

## Run TypeScript

- `tsc`: Compiles to JavaScript.
- `tsx`: Runs a `.ts` file directly in development.
- Vite, Next.js: Compile TypeScript without `tsc`, which is used only to check the types.

```console
npx tsx src/index.ts
```
