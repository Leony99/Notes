# Functions

## Parameters and return

*Example:*

```typescript
function greet(name: string, greeting = "Hello", suffix?: string): string {
  return `${greeting}, ${name}${suffix ?? ""}`;
}

function sum(...numbers: number[]): number {
  return numbers.reduce((total, n) => total + n, 0);
}
```

- `greeting = "Hello"`: Default parameter, the type is inferred.
- `suffix?`: Optional parameter, must come after the required ones.
- `...numbers`: Rest parameter, always an array.

## Function types

*Example:*

```typescript
type Operation = (a: number, b: number) => number;

const add: Operation = (a, b) => a + b;

function calculate(a: number, b: number, operation: Operation): number {
  return operation(a, b);
}
```

OBS: With a function type, the parameters of `add` are inferred.

## Return types

- `void`: The function returns nothing.
- `never`: The function never finishes (throws an error or loops forever).
- `Promise<T>`: An async function.

*Example:*

```typescript
function log(message: string): void {
  console.log(message);
}

function fail(message: string): never {
  throw new Error(message);
}

async function getUser(id: number): Promise<{ id: number; name: string }> {
  return { id, name: "John" };
}
```

## Overloads

Several signatures for one implementation, when the return depends on the arguments.

*Example:*

```typescript
function parse(value: string): number;
function parse(value: number): string;
function parse(value: string | number): string | number {
  return typeof value === "string" ? Number(value) : String(value);
}

const a = parse("10"); // number
const b = parse(10); // string
```

OBS: Prefer a union or a generic when possible. Use overloads when the return type really changes.
