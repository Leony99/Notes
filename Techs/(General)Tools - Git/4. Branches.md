# Branches

A branch is an independent line of development. It allows you to work on a feature without affecting the main branch, and to join the work when it is ready.

## Use

*Example:*

```console
git branch
git branch -v
git switch feature/login
git switch -c feature/login
git branch -d feature/login
git branch -D feature/login
```

OBS: `git switch` is the modern form of `git checkout 'branch'`, and `git switch -c` of `git checkout -b 'branch'`.

OBS: `-d` refuses to delete a branch that was not merged, `-D` forces it.

## Merge

Joins another branch into the current one. If the branches diverged, it creates a merge commit with two parents.

*Example:*

```console
git switch main
git merge feature/login
```

```
A ─ B ─ C ─────── M   main
         \       /
          D ─── E     feature/login
```

## Rebase

Moves the commits of the current branch to the top of another one, creating a linear history. The commits are recreated, so they get new hashes.

*Example:*

```console
git switch feature/login
git rebase main
```

```
A ─ B ─ C               main
         \
          D' ─ E'       feature/login
```

OBS: Never rebase commits already shared with other people. Rebase only your own local branches.

| | Merge | Rebase |
|---|---|---|
| **History** | Keeps what really happened | Linear |
| **Commits** | Keeps the originals, adds a merge commit | Recreates them |
| **Safe on shared branches** | Yes | No |

## Conflicts

A conflict happens when two branches change the same lines. Git stops and marks the file:

```
<<<<<<< HEAD
const port = 3000;
=======
const port = 8080;
>>>>>>> feature/login
```

- Edit the file, leaving the final code and removing the markers.
- Add the file with `git add`.
- Finish with `git commit` (merge) or `git rebase --continue` (rebase).

*Example:*

```console
git add file.txt
git commit
```

To give up:

```console
git merge --abort
git rebase --abort
```

## Cherry-pick

Applies one specific commit to the current branch.

*Example:*

```console
git cherry-pick 'hash'
```

## Branch workflows

- **GitHub Flow**: `main` is always deployable, each change has a short branch and a pull request.
- **Git Flow**: Long branches (`main`, `develop`, `release/*`, `hotfix/*`). Used in projects with planned versions.
- **Trunk-Based Development**: Everyone integrates small changes in `main` very often.
