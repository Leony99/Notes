# Git

Git is a distributed version control system. It records the history of a project in commits, so you can go back to any version, work in parallel on branches and collaborate with other people.

<a href="https://git-scm.com/doc" target="_blank">Git Documentation</a>

<a href="https://docs.github.com/en" target="_blank">GitHub Documentation</a>

## Installation

**Windows:** Install <a href="https://git-scm.com/downloads" target="_blank">Git for Windows</a>, which includes Git Bash.

**Linux/Mac:** Install it with the package manager of the system.

Verify the installation:

```console
git --version
```

## Core concepts

- **Repository**: The project folder tracked by Git. The history lives in the hidden `.git` folder.
- **Commit**: A snapshot of the project at a given moment, identified by a hash.
- **Branch**: An independent line of development. It is a movable pointer to a commit.
- **HEAD**: A pointer to the commit you are working on, usually through the current branch.
- **Remote**: A copy of the repository hosted on another place (GitHub, GitLab, etc.).
- **Tag**: A fixed name for a specific commit, usually a version.

OBS: Git is the tool and GitHub is a service that hosts Git repositories. Git works without GitHub.

## File states

A file goes through four states, and the commands move it between them.

- **Untracked**: A new file that Git does not track yet.
- **Modified**: A tracked file that was changed, but is not in the next commit.
- **Staged**: A change marked to go in the next commit.
- **Committed**: A change saved in the history.

## Basic flow

```
Working directory  ──add──▶  Staging area  ──commit──▶  Local repository  ──push──▶  Remote repository
                                                                ▲                            │
                                                                └──────────── pull ──────────┘
```

*Example:*

```console
git init
git add .
git commit -m "first commit"
git remote add origin git@github.com:user/repo.git
git push -u origin main
```
