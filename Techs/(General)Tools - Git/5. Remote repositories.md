# Remote repositories

A remote is a copy of the repository hosted on another place. By convention, the main remote is called `origin`.

## Connect

*Example:*

```console
git clone git@github.com:user/repo.git
git clone git@github.com:user/repo.git my-folder
```

```console
git remote add origin git@github.com:user/repo.git
git remote -v
git remote show origin
```

OBS: `git clone` already creates the `origin` remote.

OBS: The SSH link (`git@github.com:...`) uses your SSH key, the HTTPS link (`https://github.com/...`) uses a token.

## Push

Sends your commits to the remote.

*Example:*

```console
git push -u origin feature/login
git push
```

OBS: `-u` links the local branch to the remote one, so the next commands can be just `git push` and `git pull`.

## Fetch and pull

- `git fetch`: Downloads the changes, but does not change your branch.
- `git pull`: Downloads and joins the changes in your branch (`fetch` + `merge`).

*Example:*

```console
git fetch origin
git log main..origin/main
git pull
git pull --rebase
```

OBS: `main..origin/main` shows the commits that are on the remote and not on your branch.

## Force push

Rewrites the history of the remote, needed after a rebase or amend of commits already pushed.

*Example:*

```console
git push --force-with-lease
```

OBS: Prefer `--force-with-lease` over `--force`. It refuses to overwrite commits that you have not seen.

OBS: Never force push on a shared branch like `main`.

## Delete a remote branch

*Example:*

```console
git push origin --delete feature/login
git fetch --prune
```

OBS: `--prune` removes the local references to branches that no longer exist on the remote.

## Pull request

A pull request (merge request on GitLab) asks to join a branch into another one, with code review in the middle.

- Create a branch and commit your work.
- Send the branch with `git push -u origin 'branch'`.
- Open the pull request on GitHub.
- After the review, merge it and delete the branch.

OBS: See Software principles → Code review.
