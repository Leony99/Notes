# Commits

A commit is a snapshot of the project. Each commit has a hash, an author, a message and a pointer to the previous commit.

## Staging

`git add` chooses what goes in the next commit.

*Example:*

```console
git status
git add file.txt
git add .
git rm --cached file.txt
```

OBS: `git rm --cached` stops tracking a file, but keeps it on the disk.

## Commit

*Example:*

```console
git commit -m "add login page"
git commit -am "fix login redirect"
```

OBS: `-a` adds the tracked files automatically. New files still need `git add`.

## Commit messages

A good message explains what changed and why. Conventional Commits is a common standard:

**type(scope): description**

- Types:
    - feat = new feature
    - fix = bug fix
    - docs = documentation
    - style = formatting
    - refactor = code change without new behavior
    - test = tests
    - chore = maintenance

*Example:*

```console
git commit -m "feat(auth): add JWT login"
git commit -m "fix(cart): prevent negative quantity"
```

## .gitignore

Lists the files that Git should not track.

*Example:*

```
node_modules/
dist/
target/
.env
*.log
```

OBS: `.gitignore` only works for untracked files. If a file is already tracked, use `git rm --cached` first.

OBS: A secret that was committed stays in the history, even after being deleted. Treat it as leaked and replace it.

## History

*Example:*

```console
git log
git log --oneline
git log --oneline --graph --all
git log --author="John"
git show 'hash'
```

## Differences

*Example:*

```console
git diff
git diff --staged
git diff main feature/login
git diff --name-only
```

OBS: `git diff` shows what is modified and not staged, `git diff --staged` shows what will go in the next commit.
