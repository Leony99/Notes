# Validation and exceptions

## Validation

Validates the data of a request with annotations. It needs the `spring-boot-starter-validation` dependency.

- `@NotNull`: Can't be null.
- `@NotBlank`: Text can't be empty.
- `@Size(min, max)`: Size of a text or list.
- `@Min`, `@Max`: Minimum and maximum of a number.
- `@Email`: Valid e-mail.
- `@Positive`: Positive number.
- `@Pattern(regexp)`: Matches a regex.

*Example:*

```java
public record CreateUserRequest(
    @NotBlank String name,
    @NotBlank @Email String email
) {}
```

`@Valid` activates the validation in the controller.

```java
@PostMapping
public UserResponse create(@Valid @RequestBody CreateUserRequest request) {
    return userService.create(request);
}
```

## Custom exceptions

*Example:*

```java
public class UserNotFoundException extends RuntimeException {
    public UserNotFoundException(Long id) {
        super("User not found: " + id);
    }
}
```

## Global exception handler

`@RestControllerAdvice` handles the exceptions of all controllers in one place. `@ExceptionHandler` chooses the exception.

*Example:*

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(UserNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public ProblemDetail handleNotFound(UserNotFoundException e) {
        return ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ProblemDetail handleValidation(MethodArgumentNotValidException e) {
        return ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, "Invalid data");
    }
}
```

OBS: `ProblemDetail` is the Spring class for the standard error format of HTTP APIs (RFC 9457).
