# Loaders

Route loaders fetch data before a route renders, in parallel with sibling routes, with built-in stale-while-revalidate caching.

*Example:*
```tsx
// src/routes/posts.tsx
export const Route = createFileRoute('/posts')({
  loader: () => fetchPosts(),
})
```
```tsx
function PostsComponent() {
  const posts = Route.useLoaderData()
  return <ul>{posts.map((p) => <li key={p.id}>{p.title}</li>)}</ul>
}
```

OBS: outside the route's own file, use `getRouteApi('/posts').useLoaderData()` instead of importing `Route` directly — it avoids circular imports.

## Reacting to search params

Loaders don't receive `search` directly — declare a `loaderDeps` function to opt in explicitly, so the cache key stays predictable.

*Example:*
```tsx
export const Route = createFileRoute('/posts')({
  loaderDeps: ({ search: { page, limit } }) => ({ page, limit }),
  loader: ({ deps }) => fetchPosts(deps),
})
```

OBS: only return the fields the loader actually uses — returning the whole `search` object causes the route to reload on every unrelated param change.

## Caching

Loader data is cached per route match and considered fresh for `staleTime` (default `0`ms, so it revalidates in the background on reuse). Preloaded data stays fresh for 30s by default.

*Example:*
```tsx
export const Route = createFileRoute('/posts')({
  loader: () => fetchPosts(),
  staleTime: 10_000, // fresh for 10s
})
```

## Handling errors

*Example:*
```tsx
export const Route = createFileRoute('/posts')({
  loader: () => fetchPosts(),
  errorComponent: ({ error, reset }) => (
    <div>
      {error.message}
      <button onClick={reset}>retry</button>
    </div>
  ),
})
```
