# Middleware

Composable logic that wraps server routes and server functions — auth, logging, CSP, context injection, before the handler runs.

*Example:*
```tsx
import { createMiddleware } from '@tanstack/react-start'

const loggingMiddleware = createMiddleware().server(({ next, request }) => {
  console.log(request.url)
  return next()
})
```
```tsx
export const Route = createFileRoute('/foo')({
  server: {
    middleware: [loggingMiddleware],
    handlers: { GET: () => { /* ... */ } },
  },
})
```

## Server function middleware

Adds `.client()`/`.inputValidator()` on top of request middleware, and can extend context.

*Example:*
```tsx
const authMiddleware = createMiddleware().server(async ({ next, request }) => {
  const session = await auth.getSession({ headers: request.headers })
  if (!session) throw new Error('Unauthorized')
  return next({ context: { session } })
})

export const getClients = createServerFn()
  .middleware([authMiddleware])
  .handler(async ({ context }) => {
    return { message: `Hello ${context.session.userId}` }
  })
```

OBS: attach auth middleware directly to every `createServerFn` that reads or writes private data — the function is its own reachable endpoint, so a route-level guard alone doesn't protect it.

## Passing context between middlewares

`next({ context: {...} })` merges data into the chain for nested middleware/handlers.

OBS: validate the *shape* of client-sent context (e.g. with Zod) and also check that the session actually has access to it — a well-formed ID isn't the same as an authorized one.

## Global middleware

Create `src/start.ts` and use `createStart()` to apply middleware to every request/function:

*Example:*
```tsx
import { createStart } from '@tanstack/react-start'

export const startInstance = createStart(() => ({
  requestMiddleware: [loggingMiddleware],
  functionMiddleware: [authMiddleware],
}))
```
