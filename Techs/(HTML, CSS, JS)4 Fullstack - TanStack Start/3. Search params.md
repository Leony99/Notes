# Search Params

URL search params are parsed as JSON (not just flat strings) and validated per route, so they behave like type-safe application state instead of raw query strings.

*Example:*
```tsx
const searchSchema = z.object({
  page: z.number().catch(1),
  sort: z.enum(['newest', 'oldest']).catch('newest'),
})

export const Route = createFileRoute('/shop/products')({
  validateSearch: searchSchema,
})
```

OBS: with Zod v4 you can pass the schema directly to `validateSearch`; for v3, wrap it with `zodValidator` from `@tanstack/zod-adapter`.

## Reading search params

*Example:*
```tsx
const ProductList = () => {
  const { page, sort } = Route.useSearch()
  return <div>...</div>
}
```

Outside the route file: `useSearch({ from: Route.fullPath })`, or `useSearch({ strict: false })` for a loosely-typed read from anywhere.

## Writing search params

The `search` prop on `<Link>` (or the `search` option on `navigate()`) updates params — pass a function to update relative to the current value.

*Example:*
```tsx
<Link to="." search={(prev) => ({ ...prev, page: prev.page + 1 })}>
  Next Page
</Link>
```

## Search middlewares

Transform search params on every generated link — `retainSearchParams` keeps specific params across navigations, `stripSearchParams` removes them when they match a default value.

*Example:*
```tsx
export const Route = createRootRoute({
  validateSearch: searchSchema,
  search: {
    middlewares: [retainSearchParams(['rootValue'])],
  },
})
```
