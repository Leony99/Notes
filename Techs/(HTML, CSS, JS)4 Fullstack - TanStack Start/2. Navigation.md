# Navigation

Every navigation in TanStack Router is relative — it always has a `from` (origin) and a `to` (destination), even when you don't write it explicitly.

*Example:*
```tsx
import { Link } from '@tanstack/react-router'

<Link to="/about">About</Link>
```

## useNavigate

For navigating imperatively as a side-effect (e.g. after a successful form submission) rather than from a click.

*Example:*
```tsx
function Component() {
  const navigate = useNavigate({ from: '/posts/$postId' })

  const handleSubmit = async () => {
    const res = await fetch('/posts', { method: 'POST' })
    const { id } = await res.json()
    if (res.ok) navigate({ to: '/posts/$postId', params: { id } })
  }
}
```

OBS: prefer `<Link>` for anything the user can click — it renders a real `<a href>`, so cmd/ctrl-click and "open in new tab" keep working. Reach for `useNavigate` only for side-effect navigations.

## Relative navigation

`to="."` reloads the current route (re-runs loaders); `to=".."` navigates to the parent route.

*Example:*
```tsx
<Link to=".">Reload current route</Link>
<Link to="..">Back to parent</Link>
```

## Active link styling

`activeProps` applies extra props/styles when the link matches the current route; pass `activeOptions={{ exact: true }}` so a link like Home isn't "active" on every child route too.

*Example:*
```tsx
<Link to="/" activeOptions={{ exact: true }} activeProps={{ style: { fontWeight: 'bold' } }}>
  Home
</Link>
```

## Preloading

`preload="intent"` (hover/focus/touch), `"viewport"`, or `"render"` fetch a route's data before the user actually clicks.

*Example:*
```tsx
<Link to="/blog/post/$postId" preload="intent">Blog Post</Link>
```
