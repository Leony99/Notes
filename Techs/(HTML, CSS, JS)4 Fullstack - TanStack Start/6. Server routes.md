# Server Routes

Server-side HTTP endpoints (GET/POST/etc.) meant to be called from outside the app — defined right alongside page routes via a `server` property in `createFileRoute`.

*Example:*
```ts
// routes/hello.ts
import { createFileRoute } from '@tanstack/react-router'

export const Route = createFileRoute('/hello')({
  server: {
    handlers: {
      GET: async ({ request }) => new Response('Hello, World!'),
    },
  },
})
```

OBS: a route file can define both a `server` handler and a page `component` at once — the same file serves the API and the UI route.

## File conventions

| Filename                 | Endpoint               |
| -------------------------- | ------------------------ |
| `routes/users.ts`          | `/users`                  |
| `routes/users/$id.ts`      | `/users/$id`                |
| `routes/api/file/$.ts`     | `/api/file/*` (wildcard)     |

## Reading params and body

*Example:*
```ts
export const Route = createFileRoute('/users/$id')({
  server: {
    handlers: {
      GET: async ({ params }) => new Response(`User ID: ${params.id}`),
      POST: async ({ request }) => {
        const body = await request.json()
        return Response.json({ message: `Hello, ${body.name}!` })
      },
    },
  },
})
```

## Status codes and headers

*Example:*
```ts
GET: async ({ params }) => {
  const user = await findUser(params.id)
  if (!user) return new Response('User not found', { status: 404 })
  return Response.json(user)
}
```

OBS: use `Response.json(data)` instead of manually setting the `Content-Type` header — it does that for you.
