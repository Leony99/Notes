# Queries and relationships

## Query operators

- Comparison: `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$in`, `$nin`
- Logical: `$and`, `$or`, `$not`
- Update: `$set`, `$unset`, `$inc`, `$push`, `$pull`

*Example:*

```typescript
Model.find({ age: { $gte: 18, $lt: 60 } });
Model.find({ $or: [{ role: "admin" }, { age: { $gt: 30 } }] });
Model.updateOne({ _id: id }, { $inc: { age: 1 }, $push: { tags: "dev" } });
```

## Query methods

Methods chained after a query, which only runs with `await`.

- `select()`: Chooses the fields.
- `sort()`: Sorts the result (1 = ascending, -1 = descending).
- `limit()`, `skip()`: Pagination.
- `lean()`: Returns plain objects, faster for read-only data.
- `countDocuments()`: Counts the documents.

*Example:*

```typescript
const page = 2;
const limit = 10;

const users = await User.find({ age: { $gte: 18 } })
  .select("name email")
  .sort({ createdAt: -1 })
  .skip((page - 1) * limit)
  .limit(limit)
  .lean();
```

## Relationships

**Embedded:** The data lives inside the document. Good for data that is always read together.

```typescript
const UserSchema = new Schema({
  name: String,
  address: { city: String, street: String },
});
```

**Reference:** Stores the `_id` of another document. Good for data that is shared or grows a lot.

```typescript
const PostSchema = new Schema({
  title: String,
  author: { type: Schema.Types.ObjectId, ref: "User" },
});
```

## Populate

Replaces a reference with the referenced document.

*Example:*

```typescript
const post = await Post.findById(id).populate("author", "name email");
console.log(post.author.name);
```

OBS: Populate runs extra queries, so avoid it in large lists.

## Indexes

Make queries faster, at the cost of slower writes.

*Example:*

```typescript
UserSchema.index({ email: 1 }, { unique: true });
UserSchema.index({ age: 1, name: 1 });
```
