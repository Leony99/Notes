# Next.js

Next.js is primarily known as a React-based framework for building server-rendered front-end applications, but it also offers powerful back-end features.

<a href="https://nextjs.org/docs" target="_blank">Next.js Documentation</a>

## Installation

**Create Next App:**

```console
npx create-next-app@latest
```

## Core concepts

- **App Router**: The routing system based on the `app` folder (version 13 or above).
- **Pages Router**: The older routing system, based on the `pages` folder.
- **Server Component**: A component rendered only on the server. The default in the App Router.
- **Client Component**: A component that also runs in the browser, marked with `'use client'`.
- **Route Handler**: An API endpoint inside the project.
- **Server Action**: A server function called directly from a form or component.

## Rendering strategies

| Strategy | When the HTML is generated |
|---|---|
| **SSG** (Static) | At build time |
| **SSR** (Server-side) | On each request |
| **ISR** (Incremental) | At build time, regenerated from time to time |
| **CSR** (Client-side) | In the browser |

## Project structure

- `app/`: Routes, layouts and pages.
- `public/`: Static files.
- `next.config.ts`: Next.js configuration.
- `proxy.ts`: Code that runs before the requests.

## Edge Runtime

Next.js introduces the *Edge runtime*, which runs JavaScript functions directly at the edge of the network (processing responses almost in real time), as close to the client as possible. This improves latency and makes responses faster as the code runs on geographically distributed CDNs.

Edge Runtime differs from Node.js because it is lighter and optimized for fast and simple operations. It lacks full access to the file system (like fs) and certain Node.js functionality that could be slower.
