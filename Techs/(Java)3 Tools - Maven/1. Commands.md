# Commands

### Quick reference

| Command | What it does | When to use |
|---|---|---|
| `.\mvnw.cmd compile` | Compiles the code | Quick error check |
| `.\mvnw.cmd spring-boot:run` | Compiles and runs in development | Daily development |
| `.\mvnw.cmd test` | Runs the tests | Validate written tests |
| `.\mvnw.cmd package` | Generates the `.jar` | Prepare for deploy |
| `.\mvnw.cmd package -DskipTests` | Generates the `.jar` without tests | Quick deploy |
| `.\mvnw.cmd clean` | Cleans `target/` | Force full recompilation |
| `.\mvnw.cmd clean package` | Cleans and generates the `.jar` | Before every deploy |
| `.\mvnw.cmd clean package -DskipTests` | Cleans, generates the `.jar`, no tests | Deploy with already validated tests |
| `.\mvnw.cmd dependency:tree` | Lists all dependencies | Investigate conflicts |

---

### Compile
```powershell
.\mvnw.cmd compile
```
Turns the `.java` files into `.class` (bytecode). It does not generate the final `.jar` and does not start the application.

**When to use:** to quickly check if the code is correct without starting anything. It is the fastest command.

```
src/main/java/**.java  →  target/classes/**.class
```

---

### Compile and run the application (Development)
```powershell
.\mvnw.cmd spring-boot:run
```
Compiles and starts the application directly, without generating the `.jar`. The application keeps running until you press `Ctrl+C`.

**When to use:** during development - it is the most used command day to day.

```
.java → .class → Tomcat starts on port 8080
```

What happens when you run this command:

1. Maven compiles the code
2. Spring Boot starts
3. Loads `application.properties`
4. Connects to the database
5. Hibernate scans the `@Entity` classes and creates/updates tables (depends on `ddl-auto`)
6. Tomcat starts on port 8080
7. Log: `Started MyProjectApplication in X seconds`

> When you press `Ctrl+C`, Spring does a **graceful shutdown** - it closes open database connections, finishes in-progress requests, and only then ends the process.

---

### Run the tests
```powershell
.\mvnw.cmd test
```
Compiles and runs all tests in `src/test/java/`.

**When to use:** after writing tests with JUnit and Mockito, to check if everything still works.

---

### Generate the `.jar`
```powershell
.\mvnw.cmd package
```
Compiles, runs the tests and packages everything in a `.jar` file inside `target/`.

**When to use:** when you want to generate the final artifact for production deploy.

```
.java → .class → tests → target/my-project-0.0.1-SNAPSHOT.jar
```

---

### Generate the `.jar` without running tests
```powershell
.\mvnw.cmd package -DskipTests
```
Same as `package`, but skips the tests. Faster.

**When to use:** when you want to generate the `.jar` quickly and already know the tests pass, or when there are no tests yet.

---

### Clean the project
```powershell
.\mvnw.cmd clean
```
Deletes the entire `target/` folder - removes all previously generated `.class` and `.jar` files.

**When to use:** when you want to guarantee a compilation from scratch, without reusing old files.

---

### Clean and generate the `.jar`
```powershell
.\mvnw.cmd clean package
```
Deletes `target/`, recompiles everything from scratch and generates the `.jar`.

**When to use:** before deploying - it guarantees the generated `.jar` has no leftovers from previous compilations.

---

### Clean and generate the `.jar` without tests
```powershell
.\mvnw.cmd clean package -DskipTests
```
Most used combination for deploy when the tests were already validated separately.

---

### View the dependency tree
```powershell
.\mvnw.cmd dependency:tree
```
Lists all project dependencies as a tree, including the transitive ones (libraries that come inside other libraries).

**When to use:** to understand where each library comes from, or when a version conflict between dependencies appears.

---

### OBS: In production

In production you don't use `spring-boot:run` - that is only for development. You generate the `.jar` and run it directly with Java:

```bash
java -jar my-project-0.0.1-SNAPSHOT.jar
```

Or via Docker (using the `.jar` inside a container). See Techs → (General)Tools - Docker.
