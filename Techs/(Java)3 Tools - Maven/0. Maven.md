# Maven

Maven is the most used **dependency manager and build tool** in corporate Java projects. It solves three main problems:

- **Dependencies** - you declare the libraries you need in `pom.xml` and Maven downloads everything automatically
- **Build** - compiles, tests and packages your application with simple commands
- **Standardization** - defines the same folder structure and lifecycle in any Java project

---

### pom.xml

The `pom.xml` (Project Object Model) is the heart of Maven - it declares who the project is, which libraries it uses and how it should be compiled.

```xml
<groupId>com.leonycosta</groupId>      <!-- who created it -->
<artifactId>project</artifactId>        <!-- project name -->
<version>0.0.1-SNAPSHOT</version>       <!-- current version -->
```

Every dependency you added in Spring Initializr (Spring Web, Spring Data JPA, Lombok, etc.) is listed in this file. When Maven runs, it reads `pom.xml` and downloads everything declared there.

---

### Maven lifecycle

Maven has a fixed lifecycle where **each phase includes all the previous ones**:

```
validate → compile → test → package → verify → install → deploy
```

This means that when you run `package`, Maven automatically runs `compile` and `test` first - you don't need to run each one separately.
