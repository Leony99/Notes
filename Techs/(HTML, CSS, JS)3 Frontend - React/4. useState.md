# useState

State lets a component "remember" a value, the value is remembered even across renders.

When the value changes, the component is re-rendered. It occurs because React needs to reflect the updated state in the UI. The re-render happens to ensure the UI is in sync with the current state.

```jsx
const [value, setValue] = useState(initialValue)
```

*Example:*

```jsx
import { useState } from 'react';

function MyComponent() {
  const [age, setAge] = useState(28);
  const [name, setName] = useState('Taylor');
  const [todos, setTodos] = useState(() => createTodos());

  function handleClick() {
    setAge(28 + 1);
    setName('John');
  }
  // ...
}
```

OBS: Never call the set function directly in the body of the component, as it causes an infinite loop of renders.

## Updating from the previous value

The state only changes on the next render. Pass a function to use the most recent value.

*Example:*

```jsx
function handleClick() {
  setCount((prev) => prev + 1);
  setCount((prev) => prev + 1); // count + 2
}
```

## Objects and arrays

State must be treated as immutable. Create a new object or array instead of changing the existing one.

*Example:*

```jsx
setUser({ ...user, name: 'John' });

setTodos([...todos, newTodo]);
setTodos(todos.filter((todo) => todo.id !== id));
setTodos(todos.map((todo) => (todo.id === id ? { ...todo, done: true } : todo)));
```

OBS: `user.name = 'John'` does not re-render, as React compares the reference of the object.
