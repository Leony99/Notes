# Docker Compose

Docker Compose defines and runs multi-container applications in a single YAML file, instead of several `docker run` commands. The file is usually called `compose.yaml` or `docker-compose.yml`.

<a href="https://docs.docker.com/compose/" target="_blank">Docker Compose Documentation</a>

## Structure

- `services`: The containers of the application.
- `volumes`: The named volumes.
- `networks`: Custom networks (optional).

Compose creates a network for the project automatically, so each service reaches the others by the **service name**.

*Example (Spring Boot + PostgreSQL):*

```yaml
services:
  api:
    build: .
    ports:
      - "8080:8080"
    environment:
      SPRING_DATASOURCE_URL: jdbc:postgresql://db:5432/app
      SPRING_DATASOURCE_USERNAME: ${DB_USER}
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD}
    depends_on:
      db:
        condition: service_healthy
    restart: unless-stopped

  db:
    image: postgres:16
    environment:
      POSTGRES_DB: app
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - db-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER} -d app"]
      interval: 5s
      timeout: 3s
      retries: 5

volumes:
  db-data:
```

## Service properties

- `image`: The image to use.
- `build`: The path to build an image from a Dockerfile.
- `ports`: Published ports (host:container).
- `environment`: Environment variables.
- `env_file`: Environment variables from a file.
- `volumes`: Volumes and bind mounts.
- `depends_on`: Services that must start first.
- `healthcheck`: Command that checks if the service is healthy.
- `restart`: Restart policy.
- `command`: Replaces the default command of the image.

OBS: `depends_on` alone only waits for the container to start, not for the application inside it to be ready. To wait for the application, use `condition: service_healthy` with a `healthcheck`.

## Environment variables

Compose reads the `.env` file next to the Compose file and replaces the `${VAR}` values.

*Example:*

```
DB_USER=app
DB_PASSWORD=secret
```

OBS: Add `.env` to `.gitignore`. Never commit secrets.

## Commands

```console
docker compose up
docker compose up -d
docker compose up -d --build
docker compose down
docker compose down -v
docker compose ps
docker compose logs -f api
docker compose exec api sh
docker compose restart api
```

OBS: `docker compose down -v` also deletes the named volumes, and the data with them.

OBS: The old `docker-compose` command (with a hyphen) was replaced by `docker compose`.
