# Containers

A container is a running instance of an image. It is isolated from the host and from other containers, and everything written inside it is lost when it is removed.

## Run

**docker run [options] image [command]**

- Options:
    - -d = run in the background (detached)
    - -p = publish a port (host:container)
    - --name = container name
    - -e = environment variable
    - --env-file = environment variables from a file
    - -v = volume or bind mount
    - --network = connect to a network
    - --rm = remove the container when it stops
    - -it = interactive terminal
    - --restart = restart policy (no, on-failure, always, unless-stopped)

*Example:*

```console
docker run -d --name my-app -p 3000:3000 -e NODE_ENV=production my-app:1.0.0
```

```console
docker run --rm -it node:20-alpine sh
```

OBS: In `-p 8080:3000`, the application listens on port 3000 inside the container and you access it on `localhost:8080`.

## Lifecycle

```
created → running → stopped → removed
```

```console
docker stop my-app
docker start my-app
docker restart my-app
docker rm my-app
docker rm -f my-app
```

OBS: `docker stop` sends SIGTERM to the process and, after 10 seconds, SIGKILL. `docker rm -f` removes a running container.

## List

`docker ps` shows the running containers and `-a` also shows the stopped ones.

```console
docker ps
docker ps -a
```

## Debug

**Logs:** `-f` follows the output.

```console
docker logs my-app
docker logs -f my-app
```

**Open a terminal inside a running container:**

```console
docker exec -it my-app sh
```

**Other information:**

```console
docker inspect my-app
docker stats
docker top my-app
```

## Copy files

```console
docker cp my-app:/app/logs/error.log ./error.log
docker cp ./config.json my-app:/app/config.json
```
