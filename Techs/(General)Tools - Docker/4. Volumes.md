# Volumes

The data written inside a container is lost when it is removed. Volumes keep the data outside the container, so it survives when the container is recreated.

- **Named volume**: Managed by Docker. Used for persistent data, like a database.
- **Bind mount**: A folder of the host mounted in the container. Used in development, to see code changes without rebuilding the image.
- **tmpfs**: Stored only in memory. Used for temporary or sensitive data.

## Named volume

**-v volume-name:container-path**

*Example:*

```console
docker volume create db-data
docker run -d --name db -v db-data:/var/lib/postgresql/data -e POSTGRES_PASSWORD=secret postgres:16
```

OBS: If the volume does not exist, `docker run` creates it.

## Bind mount

**-v host-path:container-path**

*Example:*

```console
docker run -d -p 3000:3000 -v "$(pwd)":/app -v /app/node_modules my-app:dev
```

OBS: `-v /app/node_modules` keeps the `node_modules` of the image, otherwise the host folder would hide it.

OBS: In Windows PowerShell use `${PWD}` instead of `$(pwd)`.

## Read only

Add `:ro` to mount in read-only mode.

*Example:*

```console
docker run -d -v ./nginx.conf:/etc/nginx/nginx.conf:ro nginx:alpine
```

## Manage

```console
docker volume ls
docker volume inspect db-data
docker volume rm db-data
docker volume prune
```

OBS: Removing a container does not remove its named volumes. `docker volume rm` and `docker volume prune` delete the data permanently.
