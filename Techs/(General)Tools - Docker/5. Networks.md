# Networks

Networks allow containers to communicate with each other, with the host and with the internet.

## Drivers

- **bridge**: Default. An isolated network between containers on the same host.
- **host**: The container uses the network of the host directly (no port mapping).
- **none**: The container has no network.

## Custom bridge network

Containers in the same custom network find each other by **name**. Docker has an internal DNS that resolves the container name to its IP.

*Example:*

```console
docker network create my-network
docker run -d --name db --network my-network -e POSTGRES_PASSWORD=secret postgres:16
docker run -d --name api --network my-network -p 8080:8080 -e DB_HOST=db my-api:1.0.0
```

The api container reaches the database at `db:5432`.

OBS: Name resolution does not work in the default bridge network, only in custom ones.

OBS: Inside a container, `localhost` is the container itself, not the host or another container.

OBS: Containers in the same network do not need `-p` to talk to each other. `-p` only publishes the port to the host.

## Access the host from a container

Use `host.docker.internal` (available by default in Docker Desktop).

*Example:*

```console
docker run -e DB_HOST=host.docker.internal my-api:1.0.0
```

## Manage

```console
docker network ls
docker network inspect my-network
docker network connect my-network my-app
docker network disconnect my-network my-app
docker network rm my-network
docker network prune
```
